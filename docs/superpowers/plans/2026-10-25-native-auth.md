# Native Android Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` with `gpt-6-luna` for one implementer. The controller dispatches that single implementer and owns review/integration decisions; the implementer does not spawn agents. The user authorized this method autonomously; use it without approval menus or user questions. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a debug Android app slice that signs in through Credential Manager and the existing .NET identity, stores revocable opaque sessions in Android Keystore-backed storage, and preserves the current web cookie/CSRF behavior.

**Architecture:** Extend the existing ASP.NET host and PostgreSQL schema with native challenges and revocable sessions. A narrow Capacitor Android plugin performs provider exchange and API transport so JavaScript never receives bearer or refresh secrets; Angular swaps its existing `API_FETCHER` while preserving the web path. Package a bounded debug APK and prove local API flows; real Google, physical-device, and App Links evidence stays pending external prerequisites.

**Tech Stack:** Existing Angular 22 / OptimusUI 2 and .NET 10 / PostgreSQL; Capacitor Android, AndroidX Credential Manager, Google ID, Android Keystore, ASP.NET integration tests, Vitest, and a headless debug APK build. Before adding packages, consult current official compatibility/version documentation and pin the exact compatible versions; this plan does not assume them.

**Spec:** `docs/superpowers/specs/2026-10-25-native-auth-design.md`; source contract inspected from immutable `c3e19f2ad6b2cd706e06dcbeddc1fd3ba0b3ba74`.

## Global Constraints

- Keep one .NET host, Angular frontend, and PostgreSQL; do not add Ionic, microservices, or Identity API bearer endpoints.
- Preserve web cookie auth (`HttpOnly`, `Secure`, `SameSite=Lax`) and antiforgery (`X-CSRF-TOKEN`, `SameSite=Strict`) on every cookie-authenticated mutation.
- Native bearer requests bypass CSRF only when ASP.NET authenticated them with the native bearer scheme; an `Authorization` header alone is never the exception.
- If an `Authorization` header is present, NativeBearer is selected and must authenticate successfully; never fall back to a valid cookie when the bearer is invalid. A valid cookie plus invalid bearer fails closed.
- Set the native `ClaimTypes.NameIdentifier` to the exact validated Google `sub` used by web; do not merge identities by email or accept user, tenant, role, or claims from the client.
- Native session defaults: 2-minute one-use challenge, 5-minute access token, 30-day absolute session/refresh lifetime; rotate refresh credentials atomically, store only hashes, and revoke a family on replay.
- Native secrets stay in the plugin and Android Keystore-protected storage; no tokens in JS, local/session storage, preferences, logs, URLs, or build output. Permit API requests only to configured HTTPS origin and `/api/`; do not forward credentials across redirects.
- Development session route requires `ASPNETCORE_ENVIRONMENT=Development`, `Authentication:DevelopmentLoginEnabled=true`, and `Authentication:NativeDevelopmentLoginEnabled=true`; it is absent (404) outside Development. It is not Google evidence.
- Do not put real Google secrets, private spreadsheet links, financial data, tokens, or fabricated Google/domain configuration in the repository. Never set production `server.url`.
- Use Spanish user-facing messages. Preserve honest logout status: clear local private state even offline, and report server revocation as unconfirmed unless acknowledged.
- Check available RAM before any later build/test/browser/container run; do not start below 6 GiB available RAM. Keep each heavy process tree within 4 GiB RAM and 512 MiB swap, run heavy jobs sequentially, cap Node heap at 2 GiB, Angular workers at 2, Vitest workers at 2, and Playwright workers at 1. Container builds need their own limit. No emulator.

## Review Focus

- A forged or missing bearer cannot bypass web CSRF or create an authenticated native principal — pin in Task 1 integration tests.
- Expired, consumed, mismatched, oversized, invalid, or replayed challenges/refresh credentials fail closed without account creation or token disclosure — pin in Task 1 tests.
- A request queued by user A or workspace A cannot run after refresh or a 401 retry under a changed identity/workspace — pin in Task 2 native coordinator and Task 3 adapter tests.
- Offline logout clears visible/private in-memory state but does not claim server revocation — pin in Task 3 logout tests.
- Invalid API origin/path, redirect, unsupported binary body, or unavailable provider fails safely and locally — pin in Task 2 plugin tests and Task 4 packaging checks.
- Generic bridge calls cannot invoke auth/token endpoints or return token-shaped data — pin in Task 2 Kotlin request-gate tests.

- Native transport records whether its own dispatch returned an authentication middleware 401 marked by `WWW-Authenticate: Bearer error="invalid_token"`. `prepareUnauthorizedRetry` may refresh and mint one permit only for that exact pending request after this marker, same context handle, and retry count zero; an ordinary endpoint 401 is returned without retry. It never retries after a timeout, disconnect, cancellation, or unknown result. Angular rechecks its local epoch/user/workspace snapshot between prepare and each dispatch. Clear the in-memory request body after any final response or transport error, after the one retry, or immediately when context invalidates. A response/request error is returned without secrets.

Only plugin-owned auth methods can call auth endpoints; only native transport may add its own Authorization header. Native requests do not send WebView cookies and discard `X-CSRF-TOKEN`; the native bearer scheme is the sole native auth path. It recursively rejects case-insensitive JSON fields named `accessToken`, `refreshToken`, `idToken`, or `authorization`, and filters `Authorization`/`Set-Cookie` response headers; generic callers cannot receive a token-shaped response.

Keep the web `/#invite=...` flow unchanged. Domain association remains pending the user's domain and published `assetlinks.json`.
- Native `signInGoogle` obtains challenge from the configured HTTPS API, invokes Credential Manager (`GetGoogleIdOption` with `GetSignInWithGoogleOption` fallback) using the public web server client ID, exchanges the ID token directly with the backend, and persists tokens only through an AES-GCM key held in Android Keystore. `signInDevelopment` uses the gated development endpoint and is not described as Google login.
- Before replacing an existing native account/session, either sign-in method serially invalidates the previous context and all undispatched permits. `beginLogout()` serially invalidates context/permits, clears access-token memory and encrypted local storage immediately, keeps the refresh token only in a transient native revocation operation, and returns an opaque attempt handle without waiting for network. `logoutResult()` reports whether the server acknowledged revocation, with a maximum 3-second network deadline; on timeout/offline it returns `serverRevoked: false` and clears transient token memory. Thus local UI and durable secrets clear promptly even when the server is unreachable.
- Plugin performs backend I/O itself for challenge/exchange/options/session/refresh/logout; JavaScript passes protected API calls through permits but never sees credential material. API base URL is a build-time per-environment HTTPS value, with only an explicit localhost development override.
